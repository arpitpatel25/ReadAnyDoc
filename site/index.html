The open-source alternative to Reducto

Parse and extract PDFs, scans and forms with Claude or any vision model. Same API as Reducto, so you switch by changing one URL. Runs on your own model account, at a fraction of the price.

Same API as Reducto

Point Reducto's own SDK at your ReadAnyDoc server. Parse, extract, split, classify, edit, jobs and webhooks answer in the same format, so existing code keeps working.

Your model, your account

Documents go straight to the model provider you choose, under your own key. Claude Haiku 5.5 by default; any Claude, OpenAI or self-hosted model works.

A fraction of the price

About $0.003 to $0.005 a page with the full engine, or $0.001 to $0.002 reading pages with the model alone. Reducto charges $0.01. There is no fee on top.

Everything Reducto does, in the open

One library and one server for every document task.

Parse

Pages become typed blocks (text, tables, forms, figures) with positions, plus Markdown for your LLM.

Extract

Pass a pydantic class or JSON schema and get it back filled in, with a citation for every value.

Split

Find where each document starts and ends inside one combined PDF.

Classify

Label documents by type, with the text that supports the label.

Edit

Fill in PDF forms, including flat and scanned ones.

Jobs and webhooks

Send large batches asynchronously and get notified when each one is done.

Start in a minute

Use it as a Python library, or run the server and call it from any language.

Python library

import readanydoc

result = readanydoc.parse("statement.pdf")
print(result.markdown)

invoice = readanydoc.extract("invoice.pdf", schema=Invoice)
print(invoice.data.total)

How we built it

Reducto trained its own model. We bet that a general model plus careful software could match it, and keep getting better every time the models do. Four days, 272 experiments, all written down.

  1. The model could already read

    Plain Claude Haiku matched Reducto's own model at reading text and tables, for a fifth of the price. What it lacked was structure: layout, forms, headers, and where each value came from.

  2. Most clever ideas failed

    Asking the model twice, cheaper images, compact formats: most made things worse. What worked was a different view of the page, like zoomed re-reads that must agree before a digit changes.

  3. We stopped trusting small tests

    On 100 tables we looked ahead of Reducto. On all 1,000 we were level. We dropped AI judges and small samples and ran every benchmark in full, with its own grader.

  4. We built the whole product

    The value turned out to be everything around the model: layout, citations, typed extraction, long documents, jobs, and Reducto's API. That is what ReadAnyDoc gives away.

Questions

Is it really free?

Yes. ReadAnyDoc is Apache-2.0. You pay only your model provider for the calls it makes, and every result tells you what those calls cost.

Which models can I use?

Any Claude model, OpenAI models, or a model you host behind an OpenAI-compatible server such as vLLM. You set the model, effort and request options per call. The benchmarks above use Claude Haiku 5.5, with Sonnet 5.5 for handwriting.

Is it as good as Reducto?

Ahead on reading text, level on tables and forms, behind on page layout, formulas and speed. The full numbers and how we measured them are in the benchmarks.

Where do my documents go?

To your machine and to the model provider you configure, under your account. Nothing goes to us. With a self-hosted model, nothing leaves your network.

Do I need to run a server?

No. pip install readanydoc and call it from Python. Run the server only if you want the Reducto-compatible API or call it from other languages.

What is the difference between engine and model only?

Model only sends each page to the model once: cheapest and fastest. The engine adds layout, form fields, table checks, zoomed re-reads of scans and word-level citations, for about two to three times the model cost.
